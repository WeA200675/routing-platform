# G6.20 Physical Device Gate

Run only after implementation and CI are green and after an actual runtime/model artifact has passed the provenance gate.

## Required device evidence

Target device: project physical Pixel test device.

1. Enable airplane mode and separately verify Wi-Fi/mobile data are unavailable.
2. Cold-load the SHA-256-pinned GGUF artifact through the managed lifecycle.
3. Record model load time and process memory before/after load.
4. Generate 20 representative conversation responses and record p50/p95 latency.
5. Generate 10 navigation-status responses; confirm route facts are supplied deterministically and cannot be mutated by generated text.
6. Exercise critical-guidance context; confirm nonessential social behavior remains suppressed.
7. Cancel 10 in-flight generations; confirm no unverified partial text is presented.
8. Background/foreground the app five times with a loaded model; confirm lifecycle remains valid or fails closed.
9. Force low-memory conditions; confirm admission rejects loading below the configured memory floor.
10. Unload the model and confirm memory is reclaimed sufficiently for normal navigation operation.

## Pass criteria

- zero network dependency for inference
- zero navigation-authority mutations from model output
- zero presentation of unverified partial tokens
- zero crashes/ANRs during the sequence
- all hashes/provenance shown by the test build match the reviewed artifact
- latency and memory measurements recorded in the G6.20 acceptance evidence

Do not merge G6.20 until this gate is completed for the actually selected distributable runtime/model combination.


## Machine-checkable measurement record

Device performance evidence is represented by `SocialAiDevicePerformanceEvidence`.
It stores only sample count, cold-load duration, process-memory snapshots and
generation latency durations. Prompt text, generated text, recalled memory,
route facts and location data are deliberately excluded.

At least 20 generation samples are required. p50 and p95 are derived
deterministically from those samples, and unload evidence must demonstrate
positive memory reclamation. These checks validate the shape and consistency of
the physical evidence; they do not invent a performance threshold or replace
the Pixel device run for the selected runtime/model pair.

Critical memory or thermal pressure now deterministically unloads a loaded
model and revokes its verified lease. Returning to a healthy resource state
never reloads model bytes automatically; a fresh explicit, fully verified load
is required.


## Machine-checkable safety record

`SocialAiDeviceSafetyEvidence` records only counters needed for physical
acceptance. A valid record requires at least one offline inference request,
10 navigation-authority checks, 10 cancellation checks and 5
background/foreground cycles. Acceptance is fail-closed when any offline
failure, navigation-authority mutation, unverified partial output or lifecycle
failure is recorded. The counters contain no prompt, response, route or
location content and do not replace execution of the manual Pixel test steps.
