# G10 Acceptance — Production Release

This document is normative because the repository contained no prior G10 acceptance specification.

G10 is complete only when all criteria below are satisfied on one immutable release candidate.

1. Every automated acceptance criterion for G6–G9 is green on the exact release-candidate SHA.
2. Release Android routing endpoints require HTTPS. Loopback cleartext is debug-only and no production build contains an implicit network fallback.
3. The on-device AI model/runtime inputs are pinned and integrity-checked; model failure cannot mutate authoritative navigation state.
4. Routing/provider failures, malformed contracts, unsupported capabilities, stale callbacks and missing data fail closed without inventing coordinates, traffic or routing properties.
5. Release artifacts and their hashes are generated by CI from the exact candidate SHA; workflow actions and externally consumed immutable inputs are pinned or integrity verified.
6. Debug-only exported diagnostic surfaces are absent from the release manifest.
7. A final physical-device package verifies normal product flow, precise-location permission behavior, local AI lifecycle, real route preview/navigation, cancellation/restart, background/foreground behavior and absence of silent fallback.
8. Real-road/traffic claims require provider evidence. Plain OSRM is accepted as real OSM routing but explicitly not as live traffic.
9. G10 is not marked complete until the final physical-device evidence is attached to the exact candidate and all automated pipelines for that SHA have succeeded.
