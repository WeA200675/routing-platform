# G6.20 Local Inference Security Boundary

## Deterministic authority

The local LLM is a presentation component only. It does not own or mutate route
geometry, positioning, maneuver truth, progress state, permissions, emergency
behavior or critical-guidance policy.

## Input admission

Before native inference, model-facing input is bounded by deterministic limits:
user text, recalled memory, total prompt characters and output tokens. Memory is
sanitized before admission. Model files are regular local files whose SHA-256
must match immutable metadata before loading.

## Runtime lifecycle

Only one verified model may be active. Runtime sessions transition explicitly
between unloaded, ready and failed states. Native load or generation failures
unload the backend and fail closed; there is no implicit cloud fallback.

## Output admission

Streaming partial tokens are not presentation-safe and remain buffered. Only a
completed result with matching backend identity and local-inference assertion
may cross deterministic post-generation enforcement. Critical-guidance output
remains separately constrained.

## Networking

The Android application itself has network permissions because routing and map
features require them. Therefore offline LLM behavior cannot be inferred from
manifest permissions. The LLM runtime boundary exposes no network API and the
physical-device gate must prove inference with connectivity disabled.

## Telemetry

Inference metrics contain identifiers, character counts, elapsed time and
cancellation state only. Prompt text, output text, memory values and route data
are not telemetry fields.


## Static transport isolation

CI now scans production sources in the local AI package for network-capable
transport APIs and libraries. Introducing URL/socket APIs, OkHttp, Retrofit,
Java/Javax networking, or WebView transport into that boundary fails the unit
gate. This is intentionally package-scoped: routing and maps retain their
network permission and transport implementations outside the LLM boundary.

The static guard complements, but does not replace, the physical airplane-mode
test. Native runtime/model artifacts still require provenance review because a
source-level Kotlin scan cannot prove the behavior of packaged native code.
