# G6.20 Runtime Provenance and Distribution Gate

G6.20 defines the integration boundary but does not vendor a model or native
runtime binary by default.

A distributable local LLM package is admitted only when all of the following
are recorded together:

- runtime component id, immutable upstream revision, SPDX license and HTTPS source
- model id, immutable revision, separately reviewed SPDX license and HTTPS source
- exact model SHA-256
- GGUF format and quantization
- expected artifact bytes and minimum RAM envelope
- reproducible native build instructions for the selected runtime
- immutable native build id
- explicit Android ABI allowlist for that build
- toolchain versions
- SBOM entry for runtime and model
- offline test proving inference works with networking unavailable
- physical-device latency and memory measurements

The admission code rejects floating main/master revisions and licenses outside
the reviewed permissive set. Candidate names are not approvals.

## Runtime attestation

Runtime selection is fail-closed. An admitted backend must match the reviewed
runtime metadata and model metadata exactly, including the model SHA-256. The
current Android ABI must also be covered by the attestation for the immutable
native build. The JNI-facing engine must expose that immutable build identity,
and it must exactly match the attestation before model bytes may reach native
load. Backends that cannot identify their native build are rejected. This
prevents a reviewed model record from being silently paired with a different
native runtime, model artifact, or unreviewed ABI build.

The attestation is an application-side admission record, not a claim that a
binary is cryptographically signed. Distribution still requires reproducible
build evidence, SBOM data, and the physical offline/device gate listed above.

## Authority boundary

The native engine receives a verified local file path and bounded prompt. It
has no routing mutation interface and no cloud fallback interface. Generated
text passes through the deterministic G6.19/G6.20 social and critical-guidance
enforcement layer before presentation.


## Reproducible distribution evidence

The distribution gate now requires machine-checked build evidence in addition to
runtime attestation. Evidence binds the reviewed source package SHA-256, one
runtime artifact SHA-256 for every and only attested Android ABI, explicit
toolchain component versions, deterministic build arguments, and the SHA-256 of
the reviewed SBOM. Missing ABI hashes, malformed digests, and floating
toolchain versions such as `latest` fail closed.

This evidence record does not manufacture trust in an artifact: the recorded
source, binary and SBOM digests still have to be produced and independently
reviewed from the selected immutable upstream revision before distribution.
No runtime/model candidate is approved by these checks alone.
